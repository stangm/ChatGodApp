# Architecture review — 7 Aug 2026

An independent read of the whole codebase against the standing constraints, done after a
day of large changes (the ChatMob rename, the config cleanup, persistence, and the layer-2
merge). Reviewed with fresh context deliberately, because most of that day's code was
written in one session and the author of a change is the worst judge of it.

**Ranked by cost if ignored, not by effort.** The lens throughout: *what does this cost at
9pm when the streamer says "it stopped working"?* Silent failures, and states that look
identical to a different problem, are the expensive category. Everything else is tidying.

## Verdict

**The design holds. Neither stage F nor stage G needs a redesign.** The three-layer model,
the `reset_to()` reset point, and the seam between "who is talking" (`Player`) and "how the
slot behaves" (`SlotStore`) are the right cuts and are honoured consistently.

**`chatmob_app.py` should not be split** — see *Why not to split it*, which is a real
argument rather than a shrug.

The expensive findings are not architectural. They are places where the app is wrong and
the status panel is green. Findings 1, 2, 5 and 6 are about fifteen lines between them, and
every one of them is that same shape.

## 1. `TTSManager` was handed the wrong object — no chat message could be spoken — **FIXED**

`chatmob_app.py:1477` passed `CHARACTERS` where a `SlotStore` was expected. Both are keyed
by slot number and both hold something with a voice, so `.get()` returned a perfectly
truthy `Character`, the `is None` guard passed, and `settings.voice_name` raised
`AttributeError` on **every synthesis**. `SpeechWorker` catches and prints, so it went to a
console nobody watches.

What made it expensive rather than merely broken: captions still appeared (`announce()`
runs before the worker), and `AzureTTSManager.last_result` was still `"ok"` from the startup
chime, so **the Azure health row stayed green**. Twitch green, Overlay green, Quota green,
characters visible, nobody talking.

Introduced by the layer-2 merge earlier the same day. `tts_test.py` was updated; the app's
own entry point was missed.

**Fixed**, along with two things that stop it recurring:

- `TTSManager(slot_settings)`, with a comment at the call site naming the trap.
- `voices_manager.synthesize()` now guards with `isinstance(settings, SlotSettings)` rather
  than `is None`. **A guard that only catches `None` cannot catch the right container
  holding the wrong contents**, which is exactly what happened.
- `test_playback.py` gained `test_synthesis_wiring()` — the suites had coverage on both
  sides of synthesis and none of synthesis itself, which is why 47 green checks said nothing
  about a completely broken app. It asserts the manager reaches the *live* voice, and that
  handing it the character map returns `None` rather than raising.

## 2. `twitch_channel` defaults to Mark's own channel, so a forgotten setting is a green lie

`config.py:84-90` — `default="silverstagvt"`, `required=False`.

On the second streamer's machine, forgetting `CHATMOB_TWITCH_CHANNEL` produces a bot that
connects successfully **to Mark's channel**, a status row reading
`connected as <nick>, reading #silverstagvt` in green, no keyphrase ever matching, and Pick
Random reporting an empty pool forever.

**This contradicts `config.py`'s own reasoning.** Its docstring kills the legacy variable
fallback with *"a loud failure is cheaper than a quiet success on the wrong value"*, and
notes that the unprefixed names silently powered the only real install for months. This
default is the same failure with a shorter fuse, and worse in one respect: the resulting
status row is green with a plausible-looking channel name rather than merely absent.

The counter-argument — "it works out of the box on Mark's machine" — is a convenience that
only benefits the one machine where the failure cannot happen.

**Fix:** `default=None, required=True`, and add `CHATMOB_TWITCH_CHANNEL` to the required
list in `README.md` §2 and `SETUP_RUNBOOK.md` Stage 2 in the same commit. Three lines.
Do it before the second machine is handed over, not after.

## 3. A slot with no art can never receive art over the socket — blocks stage F

`templates/overlay.html:327` wraps the entire `.character` block — both `<img>` tags and
both name boxes — in `{% if images[n].closed %}`. The `art_changed` handler then does
`slot.find('img.mouth-closed').attr('src', ...)`, which on a slot that rendered empty is an
empty jQuery set and a silent no-op.

So **assigning a character to an empty slot mid-stream does nothing visible.** Unassigning
works, because the elements exist. Refreshing the browser source fixes it, which makes it
look like the OBS caching problem this project has already been burned by and now
cache-busts everything to avoid.

Live right now: slot 3 is `testing1`, which has no art keys, so uploading art for it will
appear to do nothing.

**This blocks stage F.** Casts exist to fill slots in one click; a cast filling a previously
empty slot silently won't draw.

**Fix:** always render the block. Drop the conditionals at `overlay.html:327` and `:330`
and emit `style="display:none"` on each `<img>` when its URL is absent — the `.toggle()`
calls in `art_changed` already manage visibility from there, and the existing image error
handler already hides broken ones.

## 4. The overlay never resyncs after a server restart

`overlay.html` handles `message_send`, `slot_active`, `art_changed`, `display_changed` and
`speak`. It has **no `state` handler**, and `overlay_here` (`chatmob_app.py:1016`) only calls
`push_status()` — it sends nothing back to the page that just announced itself.

So: the app is restarted mid-stream. OBS does not reload the page; socket.io just
reconnects. `restore_slot_state()` puts the server back to "slot 2 is out of the show", but
the overlay is still drawing slot 2 from before. There is now a character on screen the
server considers absent — it will never speak, never update, never dim. Indistinguishable
from "the app is broken". The same gap swallows any hand-edit to `characters.json` between
runs.

**Fix:** in `overlay_here()`, after registering the client, send that client its current
truth using the two events the page already understands:

```python
for n in overlay_clients[request.sid]:
    emit('art_changed', slot_payload(n))
    emit('slot_active', {'user_number': n, 'active': slot_settings.is_active(n)})
```

`emit()` inside a handler goes only to the caller. No new events, no template change, and it
makes "reload the browser source" a reliable recovery rather than a superstition.

## 5. Editing a character's default voice is silently undone by the next restart

`setup_assign()` correctly calls `save_slot_state()` after `apply_assignment()`.
`setup_character()` (`chatmob_app.py:769-771`) and `setup_upload()` (`:834-836`) both call
`apply_assignment()` in a loop — which calls `slot_settings.reset_to()` and discards the live
values — and **neither saves**.

Edit Henry Potter's default voice: the live slot resets, the overlay updates, everything
looks right. `state.json` still holds the *old* voice under the *same* character id, so the
"character changed" guard passes and `restore_slot_state()` puts the old voice back on the
next start. **"I changed it and it changed back"** is close to the worst thing to debug
remotely, because it is not reproducible in the moment.

**Fix:** `save_slot_state()` after each of the two loops. Two lines. `slot_snapshot()` reads
current live values, so it writes the newly-reset defaults and is idempotent.

## 6. A dead bot thread leaves the panel permanently inert and the status row saying "still starting up"

`startTwitchBot()` (`chatmob_app.py:1440`) has no exception handling, and `__main__` prints
the "Not set" message and **starts anyway**. If `Bot(...)` raises — a missing token being
the obvious case — the global is never assigned and the thread dies.

From then on `status_report()` reports `("Twitch", "unknown", "still starting up")` *for the
rest of the session*, and `_player_from()` returns `None` for every socket event, so Pick
Random, Choose user, TTS, In the show, voice and style are all dead — each logging to a
console nobody is reading. The panel looks alive and every control does nothing.

"Unknown" is used with real care elsewhere in `status_report()`. Here it is permanently
wrong, which is worse than "bad".

**Fix:** wrap the body in `try/except`, set a module-level `bot_thread_error`, call
`push_status()`, and check that global in `status_report()` before the `twitchbot is None`
branch. About eight lines, and it turns a silently inert app into a red row with the reason.

## 7. `restore_slot_state()` runs on the wrong thread, and its comment is stale

`chatmob_app.py:1445` says it must run on the bot thread because "the Players exist by now".
**Since the layer-2 merge that is no longer true** — it touches `slot_state`,
`slot_settings`, `library.slots`, `AZURE_VOICES` and `speech_gate_enabled`, and references
neither `twitchbot` nor `Player`. (Verified: no mention of either in the function.)

What it costs now: `bot_thread.start()` runs before `socketio.run()`, so Flask is accepting
connections while restore mutates `SlotSettings` on another thread. A page connecting inside
that window gets pre-restore values from `connect`, which fires once and is never corrected.
A `save_slot_state()` in that window writes a half-restored snapshot back to disk. And it is
skipped entirely under finding 6.

**Fix:** move the call into `__main__`, after `SpeechWorker` is constructed and before
`bot_thread.start()`. One line moved; the race, the ordering dependency and the finding-6
interaction all go together.

## 8. The gTTS fallback is unguarded, and the panel asserts a mitigation that may not exist

`azure_text_to_speech.py:259-272` sets `last_result = "fallback"` **first**, then runs gTTS
and converts with `AudioSegment.from_mp3()`, which shells out to ffmpeg — documented as
**optional** in `README.md:54`.

On a machine without ffmpeg, an Azure failure produces a panel saying *"using the robotic
backup voice"* and then total silence. A status row describing a state the app is not in is
worse than no row. Same shape for a network failure, since gTTS needs the internet and the
Azure failure that triggered it is quite likely the same outage.

**Fix:** wrap the fallback in `try/except`, set `last_result = "dead"` and append to
`last_error` on failure, and add a `"dead"` branch reading
`("Azure", "bad", f"{last_error} -- nothing will be spoken")`.

## 9. One Azure synthesizer shared across three threads, with class-level health flags

`AzureTTSManager` is constructed once and called from the `SpeechWorker` thread, the **Flask
thread** via `setup_preview()`, and the main thread at startup. Beyond the SDK-threading
question, `last_result` and `last_error` are **class attributes** clobbered by whichever call
finishes last: auditioning a voice on `/setup` while chat is being read flips the Azure
health row back to green, erasing a real chat-path failure. The status panel actively hiding
the thing it exists to surface.

**Fix:** an instance `threading.Lock()` held around `text_to_audio`'s synthesis block. Both
callers are already off the bot thread, so nothing user-facing blocks. About four lines.

## 10. Layer 3 lives below the choke point, which costs three things

The per-message prefix is implemented inside the provider adapter
(`azure_text_to_speech.py:218-232`) rather than in the app:

- **(a)** Line 219 lowercases unconditionally, so Azure never sees capitalisation or
  acronyms. *Fix: lowercase only for the prefix test, slice the original.*
- **(b)** `announce()` sends the raw text while `text_to_audio` strips the prefix, so
  `(angry) hello` is **drawn** on stream and "hello" is spoken.
- **(c)** The resolved style is computed and discarded. PROJECT-STATE's per-style-art item
  correctly requires art to follow the *resolved* style — as written that is impossible.
  Retrofitting later means changing the return type of `text_to_audio`,
  `TTSManager.synthesize`, the `SpeechWorker` payload and `setup_preview` together. Worth
  recording now even if per-style art is never built.

## 11. The overlay depends on two CDNs at stream time, and the failure names the wrong cause

`overlay.html:26-28` loads jQuery, socket.io and textfill from cdnjs and jsdelivr, plus
Roboto from Google Fonts. If any fails, the overlay renders static art and then does nothing
— no socket, no captions, no lip sync, no audio.

The panel notices, but says *"no browser sources connected -- OBS isn't open, or a source
URL is wrong"*, which names the two causes that are **not** what happened and sends the
streamer to check OBS while the app is fine and the network isn't.

**Fix:** vendor the three scripts into `static/js/` and Roboto into `static/fonts/`,
reference them through `static_v()`. No behaviour change, removes three single points of
failure, and **pre-builds stage G's font plumbing**, which needs local fonts anyway.

## 12. `BOX_HEIGHTS` and `CAPTIONS` encode the same number twice — free to fix now

`characters.py:56` has `"show_message": 79` and `:84` has `{"font": 15, "box": 85}`: two
hand-maintained numbers twelve lines apart that must stay exactly 6 apart. Fine while a
human edits both. **Stage G makes the box size user-supplied**, at which point the reported
browser-source height silently drifts and the symptom is a clipped message box.

**Fix now, while it is mechanical:** `MESSAGE_OVERLAP = 6` and derive `BOX_HEIGHTS` from
`CAPTIONS`. Same values, and stage G then has one number to make dynamic instead of two.

## Why not to split `chatmob_app.py`

1,501 lines, 15 routes, 10 socket handlers, 4 classes, 44 functions — and it should stay
that way for now, for a specific reason rather than inertia.

**Six module-level names are rebound at runtime:** `CHARACTERS`, `CHARACTERS_SOURCE`
(`apply_assignment`), `twitchbot`, `twitch_nick`, and `speech_gate_enabled`. Any extracted
module doing `from chatmob_app import CHARACTERS` captures the object that existed at import
time and never sees the rebind. A `routes_setup.py` would render a stale character map after
an assignment — silently, plausibly, and only once someone changes something mid-stream.

**That is not hypothetical: finding 1 is that exact bug, already shipped.** A split would
multiply the pattern across five files. The prerequisite for ever splitting is moving those
six names onto one mutable holder so `import state; state.characters` sees the rebind — a
bigger and riskier change than the split it enables.

**The one extraction worth doing**, and not for line count: move `_voice_label`,
`_grouped_voices`, `VOICE_OPTIONS`, `STYLE_OPTIONS`, `VOICE_GROUPS` and `VOICE_STYLE_MAP`
(~75 lines) into `voice_catalog.py`. All derived once at import, never rebound, consumed
read-only. PROJECT-STATE's ElevenLabs assessment names *these exact imports* as "the bulk of
the work" in decoupling the catalogue — so this is the one refactor that shrinks the file and
pays down a parked feature at once. Do it when you next touch the voice dropdowns.

## What stages F and G actually need

**Stage F (casts):**

1. **Blocked by finding 3** — casts fill slots, and empty slots can't receive art.
2. `Library.assign()` rewrites the whole file per call, so a six-slot cast is six rewrites,
   six broadcasts, and one bad id leaves it **half applied**. Add `assign_many(mapping)`
   that validates every id up front, mutates under the existing lock, saves once, and returns
   the changed slots.
3. Finding 5 applies — a cast route must save state or the whole cast reverts.
4. The open question *"control panel or /setup"* has a concurrency consequence: the panel
   makes it a socket event, so `Library` gets mutated from a socketio thread while `/setup`
   renders on Flask threads. `_lock` covers the mutators; `resolved()` and the template reads
   are unlocked. Low probability at N=1, but it is new concurrency — decide it deliberately.

**Stage G (appearance):** the server half is as cheap as PROJECT-STATE claims — `size_parts()`
has four call sites and `BOX_HEIGHTS` one. **The client half is not in the estimate.** The CSS
custom properties are baked into a `<style>` block at render time and `CAPTION_FONTS` /
`BOX_HEIGHTS` into JS constants; `display_changed` only toggles classes. Applying appearance
live needs a new handler that rewrites the properties, reassigns those constants, and re-runs
`refit()` — because textfill writes an inline `font-size` that beats everything. That is the
real work, and it is in the file that can't be unit-tested. Findings 11 and 12 are both
prerequisites.

## What is good — leave it alone

- **The three-layer model and the `Player` / `SlotStore` seam.** Correct cut; don't re-split.
- **`SpeechPacer` timing from the clip, not from client acks.** A client-driven queue mutes
  the whole show when a page drops. Don't "improve" this.
- **The separate `_preview_cache`**, and the `SPEECH_QUEUE_MAX * 2 < AUDIO_CACHE_SIZE`
  assert. An invariant that fails at import beats 404s on stream. More of these.
- **`static_v()` / `art_url()` mtime cache-busting**, and the `done()` latch in the overlay.
- **`Library.save()` preserving unknown top-level keys** — this is what makes F and G
  additive rather than migrations.
- **The upload path**: ids as filenames, magic-byte validation, the pair validated together
  before either is written. No notes.
- **`usage.py` treating "unknown" as a real answer**, and `status_report()` refusing to say
  "bad" when it means "don't know yet". That instinct is what makes the panel trustworthy —
  and precisely why findings 1, 2, 6 and 8 hurt: each makes the panel assert something it
  doesn't know.
- **The comment density.** Excessive by normal standards, correct for this project. Every
  comment checked against the code was accurate except the stale one in finding 7 — that hit
  rate is the main reason someone who didn't write this could support it.

## Notes on the day's code specifically

- **`slots.py`** — right seam. But `SlotStore.__init__(self, slots)` names its parameter
  `slots` while receiving `{number: Character}`, and `TTSManager.__init__(self, slot_store)`
  receives a `SlotStore`. Two different objects both called "slots" at adjacent call sites is
  the ambiguity that let finding 1 through. Rename the parameter to `characters`.
- **`slots.py`** — `set_display()` rejects unknown flags, but `set_voice_name()` and
  `set_voice_style()` accept anything. That is backwards: an unknown flag is inert, an unknown
  voice reaches Azure, and an unsupported style renders neutral *without complaint*. The live
  setter is the only unguarded door and its values get persisted. Add the `AZURE_VOICES` check.
- **`slot_state.py`** — cleanest file in the change. But `flush()` is never called by the
  app, only by tests, so the "for a clean shutdown" docstring asserts something untrue.
  Either `atexit.register(slot_state.flush)` or drop the claim.
- **`config.py`** — finding 2 aside, the strongest-reasoned module in the repo.
- **The tests** — `settle()`'s idle-thread probe is worth more than the tests around it. But
  the coverage sat on *both sides* of synthesis and none on synthesis, which is how finding 1
  shipped with two green suites. Fixed.
